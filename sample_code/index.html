Before you start

Install Python

Python is the programming language we'll use. Think of it as the engine — you need it installed before anything else will work.

1

Download and install Python

Go to python.org/downloads and download the latest version. Run the installer. Important: on Windows, tick the box that says "Add Python to PATH" before clicking Install.

To check it installed correctly, open your terminal and type:

python --version

You should see something like Python 3.12.0. If you get an error, try python3 --version instead.

2

Download the sample code

We'll download three folders of sample code from GitHub. GitHub is a website where developers share code publicly — you don't need an account to download.

Go to download-directory.github.io. Paste each of these URLs into the box and click Download. You'll get a zip file each time — unzip them all into one folder on your computer.

https://github.com/XRPLF/xrpl-dev-portal/tree/master/_code-samples/get-started
https://github.com/XRPLF/xrpl-dev-portal/tree/master/_code-samples/send-xrp
https://github.com/XRPLF/xrpl-dev-portal/tree/master/_code-samples/get-tx

Each download contains a folder. Inside each folder, find the subfolder called py — that's where the Python code lives. Your folder structure should look like this:

my-xrpl-project/
├── get-started/
│   └── py/       ← work here
├── send-xrp/
│   └── py/       ← work here
└── get-tx/
    └── py/       ← work here
Before you start

Using the terminal

The terminal (also called the command line) is a text-based way to talk to your computer. It sounds intimidating but you only need three commands for this guide.

How to open it
Mac: press Cmd + Space, type "Terminal", hit Enter.
Windows: press the Windows key, type "cmd", hit Enter.
cd — change directory
Moves you into a folder. Like double-clicking a folder in Finder or Explorer, but with text.
cd get-started/py moves into that folder.
pip install
Downloads and installs a Python library. A library is a bundle of pre-written code that you don't have to write yourself.
pip install xrpl-py installs the XRPL library.
python
Runs a Python file.
python get-acct-info.py runs the sample code.
ℹ When you see a grey box with text in it, that's a command to type into your terminal. Type it exactly as shown and press Enter.
Before you start

What is the XRP Ledger?

The XRP Ledger is a blockchain — a shared record book that thousands of computers around the world keep in sync. No single company owns it. Once something is written to it, it cannot be changed or deleted.

Everything in this guide runs on the Testnet — a practice version of the ledger where the XRP has no real value. You can experiment freely without any financial risk.

Wallet
Your identity on the ledger. It has a public address (like an email address — safe to share) and a private seed (like a password — never share this).
Drops
The smallest unit of XRP. 1 XRP = 1,000,000 drops. The ledger always uses drops internally. The code converts for you automatically.
Transaction
Any action that changes the ledger — sending XRP, creating a token, etc. Every transaction must be signed with your private key before the network will accept it.
tesSUCCESS
The result code that means your transaction worked. If you see anything else, something went wrong — check the Errors tab for what each code means.
Hash
A unique fingerprint for a transaction — a long string of letters and numbers. Like a receipt number. You can use it to look up any transaction on the public explorer.
Validated
When a transaction is validated, its result is final and permanent. It will never change. This is what makes blockchain different from a regular database.
Sample 01

get-started — Connect and read

This sample connects to the XRP Ledger, creates a wallet (your identity on the blockchain), and reads that wallet's information back from the ledger. It's the "does everything work?" check.

1

Install the XRPL library

get-started/py/

In your terminal, navigate into the folder and install the library that lets Python talk to the XRP Ledger:

cd get-started/py
pip install xrpl-py

You'll see a bunch of text as it downloads. Wait for it to finish.

2

Connect to the XRP Ledger

The code connects to the Testnet — the practice version of the ledger. JsonRpcClient is how Python sends requests to the ledger, like your browser sending requests to a website.

from xrpl.clients import JsonRpcClient

JSON_RPC_URL = "https://s.altnet.rippletest.net:51234"
client = JsonRpcClient(JSON_RPC_URL)
3

Create and fund a wallet

generate_faucet_wallet() does two things at once: creates a brand new wallet (address + private key) and automatically sends it 1,000 free test XRP from the "faucet" — a service that gives out fake XRP for testing. This takes a few seconds.

from xrpl.wallet import generate_faucet_wallet

test_wallet = generate_faucet_wallet(client, debug=True)
4

Read the account from the ledger

Now we ask the ledger "what do you know about this wallet?" — it returns account data including the balance. ledger_index="validated" means we only want confirmed, final data.

from xrpl.models.requests import AccountInfo

acct_info = AccountInfo(
    account=test_wallet.address,
    ledger_index="validated"
)
response = client.request(acct_info)
print(response.result)
5

Run the file

python get-acct-info.py
What you should see — and what it means
  • A wallet address starting with the letter r — this is your public identity on the ledger
  • A balance of 1,000 XRP — the free test funds from the faucet
  • A block of data labelled account_data — this is everything the ledger knows about your wallet
  • Copy that address and open testnet.xrpl.org/accounts/YOUR_ADDRESS in your browser — you'll see the exact same information, live on the blockchain
Sample 02

send-xrp — Send a payment

This sample sends XRP from one wallet to another. Think of it like an online bank transfer — except instead of a bank processing it, thousands of computers around the world verify it simultaneously, and the record is permanent.

Every transaction on XRPL — whether you're sending XRP, creating a token, or minting an NFT — follows these exact same steps.

1

Get a funded wallet

send-xrp/py/

Navigate into the folder and install the library if you haven't already:

cd send-xrp/py
pip install xrpl-py

The sample creates a wallet with free test XRP automatically — same as in Sample 01. You don't need to set anything up manually.

2

Connect to the Testnet

import xrpl

testnet_url = "https://s.altnet.rippletest.net:51234"
client = xrpl.clients.JsonRpcClient(testnet_url)
3

Describe the payment

Here we write down what we want to do — who's sending, how much, and where it's going. xrp_to_drops(22) converts 22 XRP into drops (the unit the ledger uses internally). Think of it like converting dollars to cents before a bank processes them.

my_payment = xrpl.models.transactions.Payment(
    account=test_wallet.address,       # sender
    amount=xrpl.utils.xrp_to_drops(22), # 22 XRP in drops
    destination="rPT1Sjq2YGrBMTttX4GZHjKu9dyfzbpAYe",  # receiver
)
4

Sign the transaction

Signing proves the transaction came from you — like putting your signature on a cheque. Without it, the network won't accept the payment.

signed_tx = xrpl.transaction.sign(my_payment, test_wallet)
5

Submit and wait for confirmation

This sends the signed transaction to the network and waits until it's confirmed — usually 4 to 7 seconds. During that time, the network's validators are reaching consensus on whether to accept it.

tx_response = xrpl.transaction.submit_and_wait(my_payment, client, test_wallet)
6

Check the result

print(tx_response.result["meta"]["TransactionResult"])  # tesSUCCESS
What you should see — and what it means
  • tesSUCCESS — the transaction was accepted. The XRP has moved.
  • A transaction hash — a long string of letters and numbers. This is your permanent receipt.
  • Copy that hash and open testnet.xrpl.org/transactions/YOUR_HASH — you'll see the full record of the payment, permanently stored on the blockchain
Sample 03

get-tx — Look up a transaction

This sample looks up any transaction by its hash and checks whether it's final. This is how you verify that a payment actually happened — useful if you're building anything where you need to confirm receipt of funds.

The key concept here is validated. On the XRP Ledger, a transaction that is validated is 100% final. It cannot be reversed, disputed, or changed by anyone.

1

Set up and send a test payment

get-tx/py/ 
cd get-tx/py
pip install xrpl-py

The sample first sends a payment automatically (same as Sample 02) so there's a fresh transaction to look up. You don't need to do anything extra.

2

Look up the transaction by hash

We give the ledger a hash and it returns everything it knows about that transaction. A hash is like a tracking number — give it to anyone and they can look up the same record.

from xrpl.models.requests import Tx

tx_response = client.request(Tx(transaction="YOUR_HASH_HERE"))
3

Check that it's final

print(tx_response.result["validated"])                      # True = permanent
print(tx_response.result["meta"]["TransactionResult"])      # tesSUCCESS
What you should see — and what it means
  • validated: True — this transaction is permanently recorded. No bank, government, or company can reverse it.
  • tesSUCCESS — it succeeded. The funds moved as intended.
  • Take a hash from Sample 02 and look it up here — transactions on the ledger never disappear

Common Errors

The errors you'll hit in the first hour. Reading them is the fastest way to learn — don't skip them.

CodeWhat happenedFix
tecNO_DST Destination address doesn't exist on the ledger yet Fund the destination wallet first — an address only exists after it receives XRP
temBAD_AMOUNT Amount is zero, negative, or formatted wrong Use a positive number and make sure you're passing a string of drops, not raw XRP
tecINSUF_FEE_P Not enough XRP to cover the amount plus the transaction fee Reduce the send amount or fund the wallet again via the faucet
tefPAST_SEQ Sequence number has already been used Don't reuse a signed blob — each signed transaction can only be submitted once
txnNotFound The hash doesn't exist, or the transaction hasn't confirmed yet Wait a few seconds and try again — or double-check the hash is correct
temBAD_FEE Fee is too low or incorrectly formatted Use client.autofill() — it sets the correct fee automatically
tecPATH_DRY No path found between sender and destination for the currency Usually happens with token payments — make sure a trust line exists first
terQUEUED Transaction accepted but waiting in the queue Not an error — just wait a few seconds, it will confirm shortly
Full reference

Every possible result code is documented in the XRPL reference. The prefix tells you the category: tes = success, tec = failed (fee still charged), tem = malformed, tef = failure before entering ledger, ter = retryable.
